# mirx

`mirx` is a Windows-only native Win32 Matrix client in Rust. The current prototype includes the typed `mirx-core` facade, the Win32 UI shell, Nix-backed Linux-to-Windows GNU cross-build tooling, Wine smoke coverage, and a DLL import gate for the release artifact.

## Status

- Vertical-slice prototype scaffold is in place.
- `mirx-core` owns the Matrix SDK runtime boundary and has offline tests plus env-gated live Matrix coverage.
- Matrix SDK timeline, state, and send-queue inputs enter `mirx-core`, which normalizes them into typed room activity/state events that Win32 stores and renders.
- Reactions, media, read-state, typing, threads, and verification slices extend that typed boundary instead of adding separate UI-only paths.
- `mirx-ui` is a native Win32 shell with deterministic Wine automation, focused snapshot coverage, and a live login/session-restore/sync/rooms/send slice through `mirx-core`.
- CI is intended to run the full local check sequence through the Nix devshell.

## Local Commands

The devshell provisions local `.rustup` and `.cargo-home` caches, installs the stable Rust toolchain with `clippy` and `rustfmt`, enables the `x86_64-pc-windows-gnu` target, and exports the MinGW pthread include/lib settings validated by the spike.

```sh
nix develop -c cargo fmt --check
nix develop -c cargo clippy --workspace --all-targets -- -D warnings
nix develop -c cargo test --workspace
nix develop -c ./scripts/cross-build.sh
nix develop -c ./scripts/wine-smoke.sh
nix develop -c ./scripts/windows-ui-tests.sh
nix develop -c ./scripts/ui-snapshot.sh
nix develop -c ./scripts/dll-gate.sh
nix develop -c ./scripts/measure.sh
```

`dll-gate.sh` checks the release exe: its DLL imports against an allowlist, that it is a Windows GUI-subsystem program, and that it carries its resources (icon, group icon, version information and the manifest, with the Common-Controls 6 dependency and Windows 10/11 as its supported OS).

`windows-ui-tests.sh` runs the Wine UI suites in parallel shards (`MIRX_UI_TEST_SHARDS`, default 12), each with its own Wine prefix, Xvfb display and temp dir, and its tests one at a time; `-- [--exact] <filter>...` runs only the tests whose names match, and each shard's output is kept in `target/windows-ui-tests/`. The `scale` suite loads 200 rooms and checks, through the refresh counters in the UI dump (rows built, rows wrapped, treebar and switchbar rebuilds), that one change costs one window's work; `-- two_hundred_rooms` runs it alone.

Normal checks remain offline and deterministic. They do not require network access or Matrix credentials.
Wine/Xvfb automation and screenshot diffs are required local gates for the Win32 shell, but real Windows remains authoritative for DPI, keyboard/input behavior, DPAPI, and installer validation. Checked by hand on real Windows, not by the gates: the layout at 125%, 150% and 200% display scaling, and on a second monitor with another scaling; no console window opens when mirx starts from Explorer; the icon shows in the taskbar, Alt+Tab, Explorer (large icons) and the tray; Task Manager lists "mirx" and Properties > Details shows the version; controls are themed and the switchbar keeps its activity colours; `mirx-ui --help` from `cmd` shows a box; a panic in an interactive run shows the error box and writes `crash.log` (and whether Windows Error Reporting adds a dialog of its own after it).
`ui-snapshot.sh` captures each case in `tests/ui-states/` after the snapshot driver's actions, and a few of them again as `<case>-dpi144` in a prefix at 144 dpi (150%), at the default frame size; its prefix lets Wine draw window captions and stops the caret blinking. A `collapse:<node>` action folds a treebar item: `space:<room_id>`, or a view (`status`, `room:<room_id>`, `thread:<room_id>|<root_event_id>`). A `dialog:<name>[:<Options page>]` action (for example `dialog:select_server` or `dialog:options:IRC/Messages`) opens a dialog over the window and must be the case's last action. So must a `drag:<line>,<offset>:<line>,<offset>` action, which presses the left button at a byte offset into one visible line of the active timeline and moves to another without releasing it, leaving the mark on screen.

## Windows Integration

mirx is a Windows GUI program: started from Explorer or a shortcut, no console window opens beside it. Run from `cmd` without a redirection it has no console output either, so `--help`, a usage error and a startup error show in a message box; with a redirection (or from a script or the test harness, which pass their own handles) they go to stdout and stderr as usual, and the exit code is always set. The exe carries its own icon, version information (Task Manager lists it as "mirx") and a manifest: Windows 10 and 11, no elevation, and the themed (Common Controls 6) look for buttons, edits, lists and the status bar. mirx is system-DPI-aware: at any display scaling its text is sharp, and every bar, list, dialog and image is laid out at the system's scaling, the window opening at 1024x768 scaled (but never larger than the screen). Moved to a monitor whose scaling differs from the main one's, it is stretched by Windows until per-monitor scaling lands. Fixedsys, the default text font, is a bitmap font with few sizes, so at 150% or more its text stays small: `/font` to a TrueType face (Courier New, Consolas) for larger text. If mirx crashes, it appends a report (version, time, thread, message, place and a backtrace) to `%LOCALAPPDATA%\mirx\ui-shell\crash.log`, says so in an error box, and ends.

## Live Matrix Checks

Live Matrix checks are opt-in and use:

- `MIRX_HS`
- `MIRX_USER`
- `MIRX_PASS`
- optional `MIRX_ROOM`

Missing or empty `MIRX_HS`, `MIRX_USER`, or `MIRX_PASS` makes the live Matrix tests return early without network access.

Supported live checks:

```sh
MIRX_HS=... MIRX_USER=... MIRX_PASS=... MIRX_ROOM=... \
  nix develop -c cargo test -p mirx-core --test live_matrix

MIRX_HS=... MIRX_USER=... MIRX_PASS=... \
  nix develop -c cargo test -p mirx-core --test live_matrix

MIRX_HS=... MIRX_USER=... MIRX_PASS=... MIRX_ROOM=... \
  nix develop -c cargo test --target x86_64-pc-windows-gnu -p mirx-ui --test automation_driver live_matrix_ui_session
```

`MIRX_ROOM` is optional for the existing login, restore, sync, and logout coverage. It is required for send coverage and for the fully-read marker verification in `live_matrix`. `MIRX_ROOM` must be a room the account has already joined; the live test creates the event-backed message itself before issuing `MarkRoomRead`.

The UI session file still lives at `%LOCALAPPDATA%\mirx\ui-shell\session.json`, but its payload is now DPAPI-protected binary data rather than cleartext JSON. The Matrix SDK SQLite store passphrase is generated per profile and persisted separately in `%LOCALAPPDATA%\mirx\ui-shell\store-passphrase.dpapi`, and refreshed Matrix access/refresh tokens are written back through the same protected session store. A browser sign-in's OAuth 2.0 tokens and client ID are saved the same way, and its refreshed tokens are saved again as the server rotates them. The password is never persisted.

The menubar follows mIRC: `File` (Connect, Disconnect, Select Server... (`Alt+E`), Log Out, Exit), `View` (Switchbar, Treebar), `Tools` (E2EE recovery, Reset E2EE Identity, Export and Import Room Keys, Verify This Session, Sessions, answering a verification, Colors... (`Alt+K`), Options... (`Alt+O`)), `Commands` (prompts for a slash command's argument and runs it), `Window` (Cascade, Tile, Arrange Icons) and `Help` (Help Topics, About mirx). Room, message and nick-list actions are on their right-click menus.

The switchbar has one fixed-width button per window, 120 pixels by default, and wraps them onto as many rows as the frame's width needs, like mIRC's switchbar with Lines set to Auto; the MDI area shrinks to fit. `/switchbar [on|off]` and `/treebar [on|off]`, or `View > Switchbar` and `View > Treebar`, toggle or set whether the switchbar and the tree of windows are shown; without an argument the View menu toggles and the command echoes the current state.

Switchbar buttons and treebar items show a window's name only; unread state shows as colour, as in mIRC: maroon for an event, red for a message, blue for a highlight, by default; `Options > Display` changes them. The colours come back after a restart, from the server's unread counts. The treebar's spaces, and windows with threads under them, have expand buttons. A collapsed item takes the strongest colour of the windows under it, stays collapsed as rooms come and go, and opens again when one of its windows is activated, for example from the switchbar. Collapsing a folder never changes the active window.

`Tools > Options...` (`Alt+O`) opens mIRC's Options window, a tree of pages: `Connect > Options` (connect on startup, reconnect and retry; see Connecting below), `IRC > Messages` (timestamps on or off and their format, with the tokens listed), `IRC > Highlight` (highlight words), `IRC > Logging` (see Logging below), `Display` (switchbar button width, 40 to 400 pixels at 100% scaling, and the switchbar's Event, Message and Highlight colours, each picked from the 16-colour palette), `Display > Tray` and `Display > Tips` (see Tray and tips below), and `Other` (the window buffer, see below). OK checks every field: a wrong one shows its page with an error box, and nothing changes until it is fixed; otherwise the settings are saved and take effect at once. Cancel or `Esc` changes nothing. As in mIRC, the tree is labelled `Category:` and the selected item names the page.

`Tools > Colors...` (`Alt+K`) opens mIRC's Colors window. A preview shows every part of a window: the treebar, a timeline with one sample line per kind of text, the editbox and the nick list. Click a part, or pick it in the drop-down, then click one of the 16 palette colours (or move with the arrow keys) to give it that colour. The items are mIRC's that mirx draws: Background; Action, Highlight, Info, Invite, Join, Kick, Mode, Nick, Normal, Notice, Other, Own, Part and Topic text; Editbox, Listbox and Treebar and their text; and Gray text (typing, reactions, reply quotes, deleted messages, messages still sending). `Reset` puts back mIRC's default colours; OK saves the scheme and every window takes it at once, Cancel changes nothing. The scheme is saved as palette indices 0 to 15 in `mirx.ini`'s `[colors]` section (`join=3`, `editbox_text=1`, ...). Unlike mIRC, error lines and messages that failed to send stay red whatever the scheme, the 16 palette colours themselves cannot be changed, and there are no named schemes to save and load. Highlight words are kept on the Matrix server, not in `mirx.ini` (see `Options > IRC > Highlight`).

Every dialog opens centred on the mirx window, in the 8-point dialog font. The first field has the focus; `Tab` and `Shift+Tab` move between the fields and buttons, `Enter` presses the default button (OK) and `Esc` cancels.

Notifications follow Matrix push rules, which live on your server and are shared with your other clients. A room's right-click menu in the treebar has `Notifications > All Messages`, `Mentions and Keywords` and `Mute`; the check shows the room's mode, or, if none was set for it, the account's default for rooms of its kind (one-to-one or group, encrypted or not), usually All Messages. Invites have no mode. A muted room's window and buttons only ever turn maroon (something happened), never red or blue, and it never flashes the frame. In a Mentions and Keywords room an ordinary message still turns it red but does not flash, even in a query; a mention or keyword turns it blue and flashes as usual. `IRC > Highlight` lists the highlight words: type one or several (`deploy, build, *help*`) and press `Add` or `Enter`, or select one and press `Delete`. A word is matched as a whole word, `*` and `?` are wildcards, and a message containing it highlights (blue) and notifies. Words another client added that only notify, without highlighting, show as `word (notify only)`; adding them again makes them highlight. The page is greyed while not connected. Both the menu and OK send the change to the server: the check and the list update when the server's echo arrives with the next sync, so a change made while disconnected shows only after reconnecting.

The Rooms List is mIRC's channels list for a server's room directory. `/list [-s server] [match text]`, `Commands > List rooms...` or `Alt+L` opens it. Without `-s` it lists the user's own homeserver, and the match text is matched by the server against names, topics and aliases. The rooms arrive page by page, up to the first 1000. The caption shows progress: `Rooms List [matrix.org] "rust" - listing...`, then `- 42 rooms`, or `- 1000 of ~5300 rooms` when the cap is hit. Click a column header (Room, Users, Name, Topic) to sort by it, and click it again to reverse; Users sorts the busiest rooms first. Double-click a row or press `Enter` on it to join the room, or to switch to its window if already joined. A new `/list` replaces the listing, and closing the window drops it.

Every join you ask for opens the room's window and makes it active, as `/join` does in mIRC: `/join`, a Rooms List row, `/query` creating a direct room, accepting an invite and `/create`. `/create <name>` creates a private, invite-only, encrypted room. `/create -public #alias [name]` creates a public room listed in the room directory under `#alias:<your server>`; the alias must be on your own server, and the name defaults to the alias.

Commands name rooms as mIRC names channels. A room argument is a room ID (`!abc:example.org`), an alias (`#ops:example.org`, canonical or alternative, case-sensitive), a short alias (`#ops`, matching any alias's localpart) or the room's display name; `/msg`, `/notice`, `/names`, `/part`, `/invite`, `/window` and `/topic` take one, and a name that fits two rooms is refused as ambiguous. `/topic` shows the active room's topic, `/topic #room` another room's, and `/topic [#room] text` sets it. A refused request about a room, such as a kick or op without the power to, prints in that room's window. `/ignore <nick|@user:server>` adds a user to the account's ignore list (`m.ignored_user_list`, shared with your other clients; the server stops sending their events), `/unignore` removes them and `/ignore` lists it; the `* Added ...` and `* Removed ...` lines print when the server's echo arrives. `/whois <nick|@user:server>` asks the user's homeserver for their profile, so it works for anyone: it prints their nick, the profile's display name in mIRC's real-name slot, the rooms you share (with their rank there) and their server. The nick list's right-click menu has `Whois`, `Devices`, `Verify`, `Query User`, `Mention/Insert Name` and a `Control` submenu (`Ignore`, `Unignore`, `Op`, `Deop`, `Voice`, `Devoice`, `Kick`, `Ban`); each item runs the typed command on the member, and is greyed when that command would refuse.

Sessions and verification. `/devices [nick|@user:server]` (`Tools > Sessions` for your own, `Devices` in the nick list menu for a member's) lists a user's sessions in the active window, as `/whois` answers: one line per session with its device ID, its name in quotes, whether it is verified, and for yours when the server last saw it and which one is this session; then `End of /DEVICES list`. `/devices delete <session>` signs out another of your sessions, after a Sign Out Session dialog whose default button is Cancel: a password account confirms with its password, typed in the dialog only; an account that signs in through the browser (OAuth 2.0) signs the session out on its account page, which mirx opens, and mirx is not told when that is done, so `/devices` shows it afterwards. This session is refused (File > Log Out signs it out), and so is an ID your account does not have. `/devices rename <session> <name>` renames one of your sessions, this one too. A user named `delete` or `rename` must be given by full ID. Another user's list opens with their identity's trust: verified, not verified, changed since you verified them, or no cross-signing (then verify one of their sessions). Trust is the crypto store's after asking their server afresh; mirx never shows a session as verified on any other say. `/verify` (`Tools > Verify This Session`) asks your other verified sessions to verify this one; `/verify <nick|@user:server>` (`Verify` in the nick list menu) asks a user to verify their identity with you, in your direct room with them, which is created if there is none; `/verify <nick|@user:server> <device>` asks that one session. The other side accepts, then both compare the emoji and confirm (`Tools > Confirm SAS`, `/verify confirm`); `/verify cancel` stops it. `/verify accept`, `/verify cancel`, `/verify confirm` and `/verify reject` answer the current verification, whoever started it, so a user named `accept` must be given by full ID. The Status window's E2EE line says whether this session is verified; a session that needs it gets a red line saying how: `/verify` from another of your sessions, or `/e2ee recover` with your recovery key. The status bar notes an unverified session.

When another user's identity changes (they reset it, or someone took over their account), every encrypted room you share with them prints a red warning, as mIRC prints a nick change in every channel: `* Warning: Bob's identity was reset; /identity accept @bob:example to accept it, or /verify @bob:example`, or, if you had verified them, that your verification no longer holds. A background window's switchbar button lights up for it. The warnings come from the crypto store's own pinned and verified identities, watched in every joined encrypted room; mirx keeps no record of its own. `/identity accept <nick|@user:server>` (`Accept Identity` in the nick list menu, enabled only while a warning stands) accepts the new identity, or withdraws your verification of it; `/verify` verifies it again. `/devices nick` says when a user changed identity. A room's watch starts from its member list on the server, so when mirx starts offline, a change made while it was away shows only when that user's identity next changes.

`/e2ee reset` (`Tools > Reset E2EE Identity...`) is for when you have lost all your other sessions and your recovery key. It replaces your cryptographic identity with a new one that this session holds: it deletes your key backup and turns recovery off first, messages you cannot read now stay unreadable, and everyone who verified you sees your identity change. The dialog says so, and Cancel is its default button. A password session confirms with the account password, typed in the dialog only; an account that signs in through the browser (OAuth 2.0) approves the reset on a page mirx opens, and mirx waits up to 2 minutes for it, printing the page's address in Status; `/e2ee reset cancel` stops the wait. Status then says whether the reset happened, or was cancelled with your identity unchanged (the backup is gone either way), and that recovery is off until `/e2ee setup`.

A message mirx cannot decrypt shows as `* Bob sent an encrypted message that could not be decrypted`, in its thread or with its reply quote like any other. When its key arrives later (from another of your sessions, from the key backup after `/e2ee recover`, or from a key file) the line turns into the message in place, and a reaction or edit that was waiting for the same key applies then; a highlight lights up its window's switchbar button. `/e2ee export [file]` (`Tools > Export Room Keys...`) saves this session's room keys to a key file, encrypted with a passphrase, and `/e2ee import [file]` (`Tools > Import Room Keys...`) reads one, from mirx or another Matrix client, so its messages decrypt. The file is a full path; without one a Save or Open dialog asks for it. A dialog then asks for the passphrase (twice for an export); it is never typed on the command line, and OK stays greyed until it will do. Anyone with the file and its passphrase can read your encrypted messages. Status says when the file is written, or how many of its keys were new, or why it could not be read: a wrong passphrase, or a file that is not a key file.

Connecting works like mIRC's. With a saved session mirx restores it and starts syncing at startup, or, with connect on startup off, restores it and waits for `File > Connect` or `/server`; without one, Select Server opens. Select Server takes a server name such as `matrix.org` (the client URL is discovered through `.well-known`), a homeserver URL, or nothing when the user is a full ID like `@alice:matrix.org`, then logs in and starts syncing. `/server [server]` and `File > Connect` reconnect a disconnected session, restore the saved one, or open Select Server; `/quit` and `File > Disconnect` stop syncing and keep the session, or cancel a sign-in or session restore still in progress, as mIRC's Disconnect cancels a connect; `File > Log Out` ends the session. A request the server is slow to answer holds up only what has to wait for it: while older history loads, lines, joins and the rest go on, and exiting never waits for the server.

A connection that drops is tried again, as in mIRC. With `Connect > Options`' `Reconnect on disconnection` on, a sync that was up and failed by itself (the network went away, the server stopped answering) logs `Disconnected: <reason>` and `Reconnecting to <server>` in Status and syncs again at once. With `Enable connect retry` on, a connect that fails, including that reconnect and a connect at startup with the network down, is retried after `Delay` seconds, up to `Retry` times: Status logs `Connect retry #1 <server>`, `#2`, and so on, and the status bar says `disconnected; retrying in 10 seconds` meanwhile. Once a sync succeeds Status says `Reconnected to <server>` and the count starts over; when the retries run out it says `Not retrying: 99 retries failed. File > Connect or /server tries again.` Both are on by default, with 99 retries 10 seconds apart; these defaults are mirx's. `File > Disconnect` and `/quit` cancel a pending retry, and `File > Connect` or `/server` tries at once. A session the server signed out (its access token no longer valid) is never retried: Status says so, and the way back is `File > Log Out`, then signing in again. Starting offline works: the saved session is restored, and the room windows appear once the server first answers. Unlike mIRC, whose retry count and delay sit behind a `Retry...` button in their own dialog, mirx puts the `Retry` and `Delay` fields on the `Connect > Options` page, greyed while retry is off, so OK checks every field in one place.

A message typed while the connection is down shows in grey, ending ` (waiting to send)`, and goes out by itself, once and in order, as soon as the server answers again; it then reads as any sent message. A message that ends ` (failed)` and stays red was refused by the server (for example, no permission to post there) and is not sent again.

Leave Password empty in Select Server to sign in with your browser, for servers and accounts without a password: those of the Matrix Authentication Service (matrix.org among them), SSO-only servers, and accounts made with "Continue with Google" and the like. User may stay empty, or hold a full user ID such as `@alice:matrix.org` to pre-fill the server's page. mirx opens the server's sign-in page in your default browser and prints its address in Status, in case no browser opened. Once you have signed in there, the page sends the browser back to mirx, which signs in and starts syncing; the page then says whether it worked. A server with OAuth 2.0 (the Matrix Authentication Service) is used through it; otherwise its single sign-on is used, and a server with neither says so and asks for a password. While mirx waits, `File > Disconnect` or `/quit` cancels the sign-in. The device name names the new session for password and single sign-on; an OAuth 2.0 server names it after the client, mirx, and shows the project's homepage on its consent page. mirx listens for the browser's return on `127.0.0.1` only, on a fresh port at an unguessable address, and only until that one sign-in ends.

Presentation settings live in `%LOCALAPPDATA%\mirx\ui-shell\mirx.ini`, next to the session file, and are saved as soon as they change:

```ini
[fonts]
text=Fixedsys,9
[timestamp]
show=on
format=[HH:nn]
[connect]
startup=on
reconnect=on
retry=on
retry_times=99
retry_delay=10
[switchbar]
show=on
buttons=120
[treebar]
show=on
[logging]
channels=off
queries=off
strip=off
timestamp=on
[tray]
always=off
startup=off
minimize=off
single_click=off
[tips]
highlights=on
queries=on
channels=off
```

`/font [-b] <size> <font name>` (or `/font` and every window's system-menu `Font...` for the font dialog) sets the one text font used by every window's text area, nick list and editbox; mIRC's default is Fixedsys 9. `/timestamp [on|off|-f format]` shows, toggles or formats line timestamps, which are in local time; the format takes mIRC `$asctime` tokens (`HH H hh h nn n ss s tt TT dd d mm m yy yyyy`, everything else literal). A missing file means the defaults; a file mirx cannot parse stops startup with an error naming the line, rather than being overwritten. The Wine test scripts pin `TZ=UTC` so timestamps are deterministic.

Logging works like mIRC's. `/log on` starts logging the active window to a file, `/log off` stops it, and `/log` says whether it is on; `/log on|off #room` acts on another room's open window. Every window with an editbox has `Logging` on its window menu, checked while the window logs. Status and room windows have logs; a thread window's `Logging` and `/log` are its room's. `Options > IRC > Logging` turns on logging automatically for channels, queries or both, from when their window first shows them joined (an invite starts once it is joined). Windows already open keep the log they have. Logs go to `%LOCALAPPDATA%\mirx\ui-shell\logs`, one file per window: `status.log`, a channel's alias or room ID, and a query's user ID, with `:` as `.` (`#rust.matrix.org.log`, `@bob.example.org.log`). Each session is appended in CRLF lines, between `Session Start:` and `Session Ident:` lines (`Session Ident: Rust (#rust:matrix.org)`) and a `Session Close:` line, with a blank line before the next session. Lines are written as the window shows them, with the timestamp format of `IRC > Messages` unless `Timestamp logs` is off, and with colour and style as mIRC control codes unless `Strip codes` is on. A log writes the lines that arrive while it is on, once each, as they show; what decides is when a line arrived, not the time the server gave it. History scrolled back to is never written. A log turned on with `/log on` or the menu starts with the next line. An automatic log also writes what arrived since the room's window last closed, so the message that reopens a closed query is in its log, and so are messages received while mirx was closed (on the first sign-in with a new profile, that is the few recent messages per room the server sends with the first sync). A message is written once it is sent. Edits and deletions do not change a line already written, nor does a message decrypting late: its log keeps the line that it could not be decrypted. Closing the window, leaving the room, `/log off` and exiting close the log. A write that fails stops the log and says why in the window.

Tray and tips work like mIRC's. With `Options > Display > Tray`'s `Place mirx in tray when minimized` on, minimizing mirx hides it behind an icon in the notification area; with it off, holding `Shift` while minimizing does the same. `Always show mirx icon in tray` keeps the icon there while mirx is on screen too, and `On startup minimize mirx to tray` starts mirx hidden in it. Double-clicking the icon (or clicking it, with `Single click on tray icon to open` on) brings mirx back, or minimizes it while it is the active application. Right-clicking the icon lists the windows in switchbar order, those with new messages checked; choosing one brings mirx back with that window active. `Options > Display > Tips` shows a tip while mirx is not the active application, for highlights and query messages by default and for every channel message if chosen; a muted room never shows one, and a `Mentions and keywords` room only for highlights. Unlike mIRC's own tip windows, a tip is a Windows notification from mirx's tray icon (shown just for it if the icon is not already there), so Windows keeps the queue and decides how long each shows, and Focus Assist applies; there is no queue size or display time to set. Clicking a tip brings mirx back with the tip's window active. The icon is mirx's own; mIRC's icon animation and `/tray` are not there.

Like mIRC, a character the text font has no glyph for draws in the first fallback font that has one, at the text font's height and on its baseline, in every text area and nick list: Segoe UI, Tahoma, Segoe UI Symbol, Segoe UI Emoji, Noto Emoji, then the Windows script fonts (Nirmala UI, Microsoft YaHei, Yu Gothic, Malgun Gothic and others), whichever are installed. Emoji are monochrome; sequences (ZWJ families, skin tones, flags) draw as their component glyphs, and invisible format characters such as variation selectors are not drawn. The Wine test prefixes get the monochrome Noto Emoji font from the devshell (`MIRX_WINE_FONTS`), so the harness chain is Fixedsys, Tahoma, Noto Emoji.

Replies and edits read like mIRC lines with a dim note. A reply has a grey quote line directly above it, `    > <Alice> are we deploying today? the build looks gr...`: the replied-to line without its timestamp, first line only, cut to 60 characters; a message that is not loaded is fetched from the server, and a redacted one reads `message redacted`. A thread message replying to its own thread's root has no quote. Double-click a quote line, or choose the message menu's `Go to Original Message`, to scroll to the message it quotes and select it; older history is loaded until it is found (the status bar says `finding the original message...`), and a quote in a thread window of a message outside the thread opens the room window. Scrolling the window meanwhile gives up. Plain-text reply fallbacks (`> <@alice:example.org> ...`) that older clients send are stripped. An edited message ends with ` (edited)`. The message right-click menu's `Reply to Message` and `Edit Message`, or `/reply <event-id>` and `/edit <event-id>` without text, arm the window's editbox: a navy line under the timeline says `* Replying to <Alice> ... (Esc cancels)`, and the next line typed there (plain, `//literal` or `/me`) is sent as the reply or the new text, while other commands leave it armed. Edit puts the message in the editbox as one would type it (`/me waves` for an emote, its formatting as mIRC codes) and is offered only for your own text and emotes. `Esc` disarms the editbox; for an edit it also clears the old text. `/reply <event-id> <text>` and `/edit <event-id> <text>` still send at once. A reply also mentions the sender of the message it answers. `Up` in the editbox stays mIRC's per-window history; it does not edit the last message.

Naming someone notifies them, as typing a nick does on IRC. Every message mirx sends lists whom it mentions (`m.mentions`), which is what servers notify by since Matrix 1.17 dropped matching names in the text: each member whose display name it contains as a whole word, ignoring case, or whose full user ID it contains, and the whole room for `@room` (if your power level lets you notify it). Where names overlap the longest wins, so `Bob Smith` names Bob Smith and not Bob. The name is sent as a pill, a link to the user that other clients show as a chip, unless several members share it: then all of them are mentioned and none is pilled. Tab completion and the nick list's `Mention/Insert Name` insert exactly such a name. The text sent is what was typed; an edit notifies only the members it newly names. The members mirx knows are those of rooms whose window was opened, so `/msg` to a room never opened may miss a name.

Formatting is typed as in mIRC, with control codes in the editbox: `Ctrl+B` bold, `Ctrl+I` italic, `Ctrl+U` underline, `Ctrl+E` strikethrough, `Ctrl+K` colour, `Ctrl+R` reverse and `Ctrl+O` to end all formatting; all but the last toggle. After `Ctrl+K` come the text colour and optionally a background, by index: `Ctrl+K 4,1red on black`, `Ctrl+K 12blue`; `Ctrl+K` alone ends colouring, `99` is the default colour, and two digits are always read, so `Ctrl+K 04` is needed before a digit. While a colour number is being typed, mIRC's colour index shows above the editbox: the 16 colours with their numbers. Clicking one types its number as two digits (replacing a digit already typed), and the editbox keeps the focus; the index goes once the number is complete, on `Esc`, or when the editbox loses the focus. `Esc` while it shows only hides it, leaving a reply or edit target armed. The 16 base colours are mIRC's: 0 white, 1 black, 2 navy, 3 green, 4 red, 5 maroon, 6 purple, 7 orange, 8 yellow, 9 lime, 10 teal, 11 cyan, 12 blue, 13 pink, 14 grey, 15 light grey; 16 to 98 are the extended palette of https://modern.ircdocs.horse/formatting. Reverse is white on black. Formatted lines are sent as Matrix HTML (`formatted_body`) beside the plain text, and received HTML is shown with the same styles: bold, italic, underline, strikethrough and colours (`data-mx-color`, `data-mx-bg-color`, `<font color>`), headings bold, lists as `* item` or `1. item` lines, quotes as `> ` lines, code blocks as they are, links as `label (https://...)`, images by their alt text, spoilers black on black. As in a browser, runs of spaces in received formatted text collapse to one; mirx sends its own with no-break spaces, so they arrive as typed. Not supported yet: formatted room topics, and mIRC codes received in plain text, which are not interpreted. Under Wine the Fixedsys text font has no italic (Wine does not slant raster fonts), so italic shows only in the fallback fonts; Windows draws it slanted.

Reactions show on a dim line under the message that names who reacted, as mIRC lists nicks: `    reactions: 👍 Alice, Bob  heart Carol, Dave, Erin +2`. Each reaction names its first three reactors by nick (a user who is not a member shows by user ID), then counts the rest; reactions keep the order they were first given in, and a long line wraps.

Every room window's window menu has `Send File...`, which opens the standard Open dialog (`Send File to <room>`) and uploads the chosen file to that room, as mIRC's DCC Send dialog does; `/sendfile` without a path opens the same dialog for the active room, and `/sendfile <path>` sends at once. Threads cannot take files yet. A file's type comes from its extension, so pictures, videos and audio arrive as such (`.png` as an image, `.mp4` as a video, `.mp3` as audio); anything else, including `.svg`, is sent as a plain file.

Find is UI-scoped. Status and Thread Find search only loaded text, while Room Find searches loaded text first and can page older room history through backfill. `/find <text>`, every window's system-menu `Find Text...`, and `Ctrl+F` all invoke the same behavior; Find does not use Matrix server-side search.

## Mouse and keys

Long lines wrap at spaces and commas, and wrapped lines are indented by two characters, as in mIRC; a word longer than a line is split. A window lays out again only the lines that changed: a new message wraps one line, and a resize rewraps only the window resized. Message windows scroll as in mIRC. The mouse wheel scrolls the window; Wine sends the wheel to the focused window, so the editbox passes it on to its window's text. In the editbox, `Page Up` and `Page Down` scroll a page, `Ctrl+Page Up` and `Ctrl+Page Down` a line, and `Ctrl+Home` and `Ctrl+End` to the top or the end while the editbox is empty (with text in it they move the caret). Reaching the top of a room window, by wheel, key or scroll bar, loads older history, one request per gesture. A window at its end stays at its end as lines arrive and when it is resized.

Each window keeps at most `Options > Other`'s `Window buffer` lines, 5000 by default (100 to 50000), as in mIRC: at its end, a window drops its oldest lines as new ones arrive, after they were shown and logged. A window scrolled back keeps every line until it returns to its end, and lowering the setting shortens the windows at their end at once. A room window's messages and its own lines count; a message's quote and reaction lines go with it. Unlike mIRC, a room window's dropped messages are not gone: scrolling to its top loads them back from the server, from the oldest line it kept. A room window keeps a message still sending and every line of a thread whose window is open, and the lines below them, so it may stay over the buffer while one is. Every window with an editbox has `Buffer` on its window menu: `Clear` empties the window, as `/clear` does (a thread window has nothing of its own to clear), and `Save...` saves its lines to a text file, by default in the logs folder under the window's log name. `/savebuf <file>` saves the active window's lines without the dialog, a relative file in the logs folder; `/savebuf` alone opens the dialog. A saved buffer has the lines as the window shows them, without colour or style codes, and without the lines about the window's state (who is typing, older history loading, what the editbox replies to).

The window keys are mIRC's. `Alt+1` to `Alt+9` activate the first nine switchbar buttons. `Ctrl+Tab` and `Ctrl+Shift+Tab` step to the next or previous window in switchbar order, wrapping round. `Ctrl+N` steps through channels only, and `Ctrl+Q` through queries only. `Alt+X` maximizes or restores the active window. `Ctrl+T` moves the focus into the treebar and back to the active window. In the treebar the arrow keys move between items and activate the windows they reach, and the focus stays in the treebar. `Left` goes to an item's folder and then collapses it; `Right` expands it. MDI's own `Ctrl+F6` still steps through windows in the order they were last active.

Dragging over text marks it in inverse video, and releasing the button copies it to the clipboard, as mIRC does. The copy is the text as received, with its timestamp and nick: a message wrapped over several lines is one line, and lines are separated by CRLF. Holding `Ctrl` on release copies the formatting as mIRC control codes. A click without a drag copies nothing.

Links are mIRC's hotlinks: the pointer becomes a hand over them, and a double-click opens them. Web addresses (`https://`, `http://`, `ftp://`, `www.`) open in the default browser. Matrix links open in mirx: a `matrix.to` permalink, a `matrix:` URI, or a bare `#alias:server` or `!id:server`. A room you are in becomes the active window, any other room is joined through the link's servers, a link to a message opens its room, and a link to a user opens a query. Nicks are hotlinks too, as in mIRC: the sender's nick on a message or action line, and a pill (a name the sender linked to its user), open a query with that user on a double-click. Punctuation that ends a sentence, and a closing bracket the link did not open, are not part of a link; `C#` and `issue#12` are not links. `/join` of a room you are already in activates its window too.
